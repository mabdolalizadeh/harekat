# SMS.ir OTP Authentication Integration & Architecture

## Overview

Harekat LMS provides an extensible, production-ready **OTP authentication system** supporting both **SMS.ir REST API v1** (Fast Send / Verify endpoint) and a **Mock/Console Provider** (for local development and automated CI testing).

The integration follows strict security guidelines:
- **No OTP in API responses:** The generated OTP is never exposed in any HTTP response body or headers.
- **No OTP in production logs:** In `smsir` mode, neither the OTP value nor the API key is logged. Only generic operational status is recorded.
- **Decoupled Architecture:** The authentication controller does not know about SMS.ir; it relies on `SmsService` which dynamically resolves the appropriate provider.
- **Fail-Closed Security:** If SMS.ir fails or is unreachable, the system does NOT silently fall back to mock mode. It invalidates the un-delivered OTP and returns a clean, user-friendly error.
- **Brute-Force & Resend Protection:** Includes configurable resend cooldowns and limits on maximum failed verification attempts.

## 1. Architecture

```text
AuthController
      │
      ▼
  SmsService (Factory & Orchestrator)
      │
      ├── MockSmsProvider  (Active when OTP_MODE=mock)
      └── SmsIrProvider    (Active when OTP_MODE=smsir)
            │
            ▼
    SMS.ir REST API (POST https://api.sms.ir/v1/send/verify)
```

### Components
- **`BaseSmsProvider` (`src/services/sms/BaseSmsProvider.js`)**: Abstract interface declaring `sendOtp({ phoneNumber, otp, templateId, paramName })`.
- **`MockSmsProvider` (`src/services/sms/MockSmsProvider.js`)**: Development and testing provider. Outputs clear console messages:
  ```text
  [OTP][MOCK] 09121234567 → 123456
  ```
- **`SmsIrProvider` (`src/services/sms/SmsIrProvider.js`)**: Production adapter adhering to the official [SMS.ir REST API Documentation](https://sms.ir/rest-api/). Calls `POST https://api.sms.ir/v1/send/verify` using `x-api-key`.
- **`SmsService` (`src/services/sms/SmsService.js`)**: Factory orchestrator resolving provider based on `OTP_MODE`.
- **`AuthController` (`src/controllers/authController.js`)**: Business controller enforcing phone normalization, cooldowns, secure token generation, brute-force tracking, and session issuance.

## 2. Environment Variables

Configure the following variables in `harekat-backend/.env`:

| Variable | Required | Default | Description |
| :--- | :--- | :--- | :--- |
| `OTP_MODE` | No | `mock` | Active delivery mode: `mock` (console logging) or `smsir` (real SMS). |
| `SMSIR_API_KEY` | If `smsir` | None | Your private API Key from the SMS.ir developers panel (`کلید وب‌سرویس`). |
| `SMSIR_TEMPLATE_ID` | If `smsir` | None | Template ID from SMS.ir Fast Send panel (`شناسه قالب ارسال سریع`). |
| `SMSIR_TEMPLATE_PARAM_NAME` | No | `Code` | Parameter variable name defined in your template (without `#`, e.g. `Code`). |
| `SMSIR_BASE_URL` | No | `https://api.sms.ir` | SMS.ir REST API root URL. |
| `OTP_EXPIRES_IN_SECONDS` | No | `120` | Expiration lifetime of the generated OTP code (2 minutes). |
| `OTP_RESEND_COOLDOWN_SECONDS` | No | `60` | Cooldown period before a user can request another OTP code. |
| `OTP_MAX_VERIFY_ATTEMPTS` | No | `5` | Maximum failed verification attempts before the OTP is invalidated. |

## 3. SMS.ir Fast Send / Verify Setup

### Step 1: Obtain API Key
1. Log into your account at [SMS.ir](https://app.sms.ir/).
2. Navigate to **برنامه‌نویسان (Developers) → کلیدهای وب‌سرویس (API Keys)**.
3. Generate a new API key.
4. Copy the key to `SMSIR_API_KEY` in `harekat-backend/.env`.

### Step 2: Create Fast Send Template (قالب ارسال سریع / Verify)
1. In the SMS.ir dashboard, go to **ارسال سریع (Fast Send / Verify)**.
2. Create a new template for OTP authentication:
   ```text
   کد ورود به مدرسه حرکت: #Code#
   ```
3. Take note of the **شناسه قالب (Template ID)** generated by SMS.ir (e.g. `123456`).
4. Set `SMSIR_TEMPLATE_ID=123456` in your `.env`.
5. If you named your variable something other than `Code` (for example, `#OTP#`), set `SMSIR_TEMPLATE_PARAM_NAME=OTP`.

> [!IMPORTANT]
> The template variable name must be specified without `#` symbols in the environment variable (e.g., use `Code`, not `#Code#`).

## 4. Complete Authentication Flow

```text
User Dashboard                     Backend API                       SMS.ir API
     │                                  │                                │
     │── 1. Enter Phone & Submit ──────>│                                │
     │                                  │── 2. Normalize Mobile          │
     │                                  │── 3. Check Resend Cooldown     │
     │                                  │      (< 60s -> HTTP 429)       │
     │                                  │── 4. Generate 6-digit OTP      │
     │                                  │      (crypto.randomInt)        │
     │                                  │── 5. Save OTP & Expire (120s)  │
     │                                  │                                │
     │                                  │── 6. Deliver OTP:              │
     │                                  │   ├── mock: log [OTP][MOCK]    │
     │                                  │   └── smsir: POST /v1/send/verify──>│
     │                                  │             (x-api-key)        │
     │                                  │<── 7. status=1 (messageId) ────│
     │<── 8. Return 200 OK (no OTP) ────│                                │
     │       { ok: true, data: ... }    │                                │
     │                                  │                                │
     │── 9. Enter OTP & Submit ────────>│                                │
     │                                  │── 10. Check Expiry             │
     │                                  │── 11. Check Attempt Count      │
     │                                  │       (> 5 -> HTTP 429)        │
     │                                  │── 12. Compare OTP:             │
     │                                  │       ├── Mismatch: HTTP 401   │
     │                                  │       └── Match: Invalidate    │
     │                                  │           OTP and issue JWT    │
     │<── 13. Return 200 with JWT ──────│                                │
```

## 5. Security & Rate Limiting Controls

### 1. Resend Cooldown
- When a user requests an OTP, their phone number is put on cooldown for `OTP_RESEND_COOLDOWN_SECONDS` (default: 60 seconds).
- Any request during this period is rejected with HTTP `429 Too Many Requests`:
  ```json
  {
    "ok": false,
    "message": "لطفاً قبل از درخواست مجدد کد، 45 ثانیه صبر کنید.",
    "data": {
      "retryAfterSeconds": 45
    }
  }
  ```

### 2. Brute-Force Defense
- Each incorrect OTP attempt increments `user.otpAttempts`.
- Upon exceeding `OTP_MAX_VERIFY_ATTEMPTS` (default: 5), the OTP is immediately destroyed (`otp = null, otpExpiresAt = null`) and the user receives HTTP `429`:
  ```json
  {
    "ok": false,
    "message": "تعداد دفعات ورود اشتباه بیش از حد مجاز است. لطفاً کد جدید درخواست کنید."
  }
  ```

### 3. Expiration Lifetime
- OTP codes expire after `OTP_EXPIRES_IN_SECONDS` (default: 120 seconds).
- Expired codes are rejected with HTTP `401 Unauthorized` and cleared from the database.

### 4. Single-Use
- Immediately upon successful validation, the OTP is set to `null`.
- Replaying the same code a second time returns HTTP `400 Bad Request`.

## 6. Testing

### Run All Backend Tests
```bash
cd harekat-backend
npm test
```

### Run Dedicated OTP Suite
```bash
cd harekat-backend
npm run test:otp
```

The test suite covers:
1. `SmsService` provider factory and environment resolution (`mock` vs `smsir`).
2. Phone normalization (`0912...`, `+98912...`, `0098912...`, Persian digits `۰۹۱۲...`).
3. Mock provider console logging format.
4. SMS.ir request structure (`/v1/send/verify`, `x-api-key`, payload formatting).
5. Error rejection and credential protection without leaking secrets.
6. End-to-end authentication in mock mode.
7. Cooldown rejection (`429`).
8. Brute-force protection invalidating OTP after 5 failed attempts.
9. Expiration handling (`401`).
10. SMS dispatch failure handling (HTTP 502 with OTP nullification).

## 7. Common Troubleshooting

| Issue | Cause | Fix |
| :--- | :--- | :--- |
| `status: 10` | Invalid SMS.ir API Key | Check `SMSIR_API_KEY` in `harekat-backend/.env`. |
| `status: 11` | Inactive API Key | Activate your key in the SMS.ir dashboard. |
| `status: 12` | IP Restricted | Add your server IP to the IP whitelist in the SMS.ir dashboard. |
| `status: 102` | Insufficient credit | Recharge your SMS.ir account balance. |
| `status: 113` | Template not found | Verify `SMSIR_TEMPLATE_ID` matches your approved template ID. |
| `status: 116` | Parameter name empty | Ensure `SMSIR_TEMPLATE_PARAM_NAME` matches the template variable. |
