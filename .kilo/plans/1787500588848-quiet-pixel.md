## Implementation Notes

### Model Fixes
- `Courses` needs `teacherId` foreign key (already used in controllers but missing from model)
- `Payments` needs `userId` foreign key (relationship defined in index.js but column missing)

### Payments Controller
- POST /api/v1/payments - create with user + type (paid/pending/failed/refunded)
- GET /api/v1/payments - list all
- GET /api/v1/payments/:id - get one
- PUT /api/v1/payments/:id - update user + type
- DELETE /api/v1/payments/:id - delete

### Auth Middleware
- Verify JWT token from `Authorization: Bearer <token>` header
- Attach `req.user` with `{ id, role }`
- 401 on invalid/missing token

### Route Structure
All routes prefixed with `/api/v1`. Admin routes nested under `/api/v1/admins/*`. Auth routes under `/api/v1/auth` and `/api/v1/admins/auth`.

### Public vs Protected
- `POST /api/v1/users` - public (OTP auth flow)
- `POST /api/v1/auth` - public
- `POST /api/v1/validate-otp` - public
- `POST /api/v1/change-phone-number` - protected (user auth)
- `POST /api/v1/admins/auth` - public
- `POST /api/v1/admins/register` - public (marked `public` in spec)
- All other routes - protected (user or admin auth depending on resource)
